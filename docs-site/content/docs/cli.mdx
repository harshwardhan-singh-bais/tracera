---
title: CLI Reference
description: Every headless subcommand of the `tracera` entrypoint.
---

TRACERA ships both an interactive TUI and a scriptable CLI. The same engine
powers both.

```bash
tracera [OPTIONS] COMMAND [ARGS]...
```

## Global options

| Option | Description |
| --- | --- |
| `-w, --workspace <path>` | Workspace root directory |
| `-p, --provider <name>` | LLM provider (`openai`, `anthropic`, `gemini`, `groq`, `ollama`, ...) |
| `-m, --model <id>` | Model ID override |

Shell completion is generated by Typer:

```bash
tracera --install-completion
tracera --show-completion
```

## Commands

### `tui`

Open the interactive TUI — the default when no command is given. Accepts the
same global options.

```bash
tracera tui
tracera            # same thing
```

### `ask`

Ask a one-shot question or run a task non-interactively. Streams agent events
(thinking, tool calls) and prints the final answer as Markdown.

```bash
tracera ask "explain the retrieval pipeline in one paragraph"
tracera ask "add a --json flag to the search command" --no-stream
```

| Option | Description |
| --- | --- |
| `--stream / --no-stream` | Stream the response (default: stream) |
| `-w, --workspace <path>` | Workspace root |
| `-p, --provider <name>` | Provider override |
| `-m, --model <id>` | Model override |

### `index`

Index the workspace codebase for retrieval. Incremental by default — only
new, modified, and deleted files are re-processed.

```bash
tracera index
tracera index --rebuild     # force a full re-index from scratch
```

The pipeline scans → parses (tree-sitter) → extracts symbols → chunks →
BM25 index + local embeddings → LanceDB vector store, and prints an index
stats table when done.

### `search`

Query the hybrid index without an LLM call.

```bash
tracera search "workspace sandbox path validation"
tracera search "retry logic" --lang python --rerank --debug
```

| Option | Description |
| --- | --- |
| `-k, --k <n>` | Number of results (default: 5) |
| `-l, --lang <lang>` | Filter by language (`python`, `js`, `ts`, ...) |
| `--rerank / --no-rerank` | Apply cross-encoder reranking (default: off) |
| `--debug` | Show retrieval scores (RRF / final / rerank) |

### `fix`

Run the autonomous fix loop: plan → retrieve → edit → test, iterating
until checks pass or the iteration budget is exhausted. A regression
baseline is taken before the run and verified after.

```bash
tracera fix "pytest tests/test_sandbox.py::test_temp_dir fails"
tracera fix "fix flaky test_runner" --max-iterations 10
```

| Option | Description |
| --- | --- |
| `-i, --max-iterations <n>` | Max fix-loop iterations (default: 5) |
| `-p, --provider <name>` | Provider override |
| `-w, --workspace <path>` | Workspace root |

### `review`

Run a self-review of the current uncommitted changes (LLM-assisted, with
structural context from the index).

```bash
tracera review
tracera review --summary "added retry handling to the indexer"
```

| Option | Description |
| --- | --- |
| `-s, --summary <text>` | Brief description of what was implemented |
| `-p, --provider <name>` | Provider override |
| `-w, --workspace <path>` | Workspace root |

### `delegate`

Hand a task to the sub-agent fleet (Researcher / Coder / Tester /
Reviewer / Debugger). The task is decomposed into steps, each role runs in
turn, and results are aggregated into a report. Sub-agents are sandboxed:
they cannot run mutating git commands.

```bash
tracera delegate "add unit tests for the memory graph tool"
tracera delegate "triage the failing tests" --parallel
```

| Option | Description |
| --- | --- |
| `--parallel` | Run independent steps concurrently |

### `memory`

Manage the persistent memory layer.

```bash
tracera memory list                          # all entries
tracera memory list --query "testing"        # TF-IDF search
tracera memory add "We use pytest with asyncio auto mode"
tracera memory status                        # layer config + storage stats
```

| Subcommand | Description |
| --- | --- |
| `list` | List entries (`-c` filter by category, `-q` search) |
| `add <content>` | Add an entry (`-c` category, default `project_fact`) |
| `clear` | Delete all entries (`-y` skips confirmation) |
| `inspect <entity>` | Show stored memories for an entity (`-k` kind, `-p` process) |
| `status` | Memory layer configuration and storage statistics |
| `graph <entity>` | Knowledge graph for an entity (`-c` concept, `-d` depth) |
| `consolidate` | Merge near-duplicate memories (`-t` threshold, `--dry-run`) |
| `worker` | Background memory-worker statistics |
| `export <entity>` | Export memories to JSON (`-o` output file) |
| `import <entity> <file>` | Import memories from JSON (`-p` process id) |

### `eval`

Evaluation & benchmarking utilities (retrieval quality and agent performance).

```bash
tracera eval dataset                    # write the example benchmark dataset
tracera eval retrieval .tracera/eval/dataset.json
tracera eval agent --tasks "find the retry logic,explain the auth flow"
tracera eval ablation
```

| Subcommand | Description |
| --- | --- |
| `dataset` | Write the example retrieval-eval dataset (`-o` output path) |
| `retrieval <dataset>` | Benchmark grep / BM25 / dense / hybrid / +reranker — Recall@k, MRR, nDCG, latency |
| `agent` | End-to-end agent benchmark — success, iterations, tool calls, tokens, cost |
| `ablation` | Compare agent arms (+BM25 / +Dense / +Hybrid / +Graph) on the same tasks |

Reports are written under `.tracera/eval/` by default.

### `mcp`

MCP server & client integration (see the [MCP page](/docs/mcp)).

```bash
tracera mcp serve                       # stdio transport
tracera mcp serve --transport sse --port 8000
tracera mcp serve --check               # list exposed tools and exit
tracera mcp connect mcp_servers.json    # merge external MCP tools
```

| Subcommand | Description |
| --- | --- |
| `serve` | Run the MCP server exposing all TRACERA tools (`-t` transport, `--host`, `-p` port, `--check`) |
| `connect <config>` | Connect to external MCP servers and merge their tools into the registry |

External servers can also be attached automatically by the TUI / `ask` when a
`.tracera/mcp_servers.json` config file is present.

### `status`

Show system status: profile, workspace, data directory, provider/model,
limits, index health, and memory entry count — plus a ranked table of every
configured provider and its key env var.

```bash
tracera status
```

### `observability`

Show live telemetry from the in-process tracker: LLM / tool / retrieval /
agent call counts, token usage, latency, and an estimated cost.

```bash
tracera observability
tracera observability --reset    # reset the counters
```

From the CLI this reflects the current process; in the TUI the same data
powers the status line and `/observability`.
